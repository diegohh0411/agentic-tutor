# Local voice tutor model landscape (2026-10-21)

**Scope and confidence.** This is a point-in-time survey for a fully local macOS voice tutor (M1 Pro/16 GB floor; M3/M4 Pro/32 GB comfortable). Model releases and rankings move quickly. Published speed numbers are not apples-to-apples: hardware, prompt length, precision, runtime warm-up, and whether timings include vocoding differ. I label community and vendor claims and recommend an app-specific benchmark before shipping. Some search-indexed 2026 reports are not primary sources; treat those numbers as directional. “TTFA” means first playable audio; many projects publish no reproducible Mac TTFA.

## Executive recommendation

Ship a **cascaded, interruptible pipeline**: streaming VAD + streaming ASR, a small text LLM that streams answer text, and chunked TTS. Use **Kokoro-82M** as the fast, low-memory voice, with **Apple AVSpeechSynthesizer** as zero-download/robust fallback (and accessibility baseline). Evaluate **Qwen3-TTS 0.6B/1.7B MLX** or Chatterbox Turbo as a higher-expression optional voice when memory and latency allow. For the tutor brain, start with **Qwen3 4B-class instruct** (or Gemma 3n E2B if measured quality/Swift deployment wins); fallback to a 1–3B model. Quantized 7B is plausible on 16 GB only with conservative context and sequential/offloaded audio stages; it is a better fit for 32 GB.

Do not make native duplex the MVP dependency. **Moshi** demonstrates ~200 ms practical GPU latency and natural barge-in, but its 7B-scale speech-text model is a weak fit for 16 GB, no robust local Mac performance evidence establishes the same latency, and it trails strong text LLMs on reasoning, instruction following, and tutoring. Keep it as a research track. A cascaded design can still feel conversational with semantic end-of-turn detection, partial transcripts, streamed LLM output, early TTS chunks, and immediate cancellation on interruption.

**Assessment:** native duplex trades explicit transcript/control and best-in-class text reasoning for natural timing and simultaneous speech. The current open model with the clearest sub-200ms claim is Moshi, but that number is for an L4 and does not transfer to an M1 Pro. For an accessibility-first tutor, predictable captions, editable transcripts, interruption/cancel, replay, rate control, and reliable explanations matter more than mimicking overlapping conversation. A carefully engineered cascade addresses those directly and can still start talking before the LLM finishes.

**Apple Silicon measurement cautions:** [Apple Silicon LLM Bench](https://github.com/john-rocky/apple-silicon-llm-bench/blob/main/LEADERBOARD.md) records dated runtime/model results, including Gemma 3 1B Q4 around 104 tok/s in one MLX-Swift run and Gemma 4 E2B QAT around 36 tok/s in another. The [LLMCheck catalog](https://llmcheck.net/benchmarks) tags measured vs estimated values and shows chip/RAM/runtime variation. These are snapshots, not guarantees. Token generation speed for short answers is usually less important than ASR endpointing, model load/warm-up, first streamed token, and TTS first chunk. Benchmark on M1 Pro and M3/M4 Pro with exactly the intended context and concurrent stack.

## Runtime and Swift integration

- **Best native application path:** SwiftUI/AVFoundation for UI, capture/playback, interruption, and captions; [MLX Swift](https://github.com/ml-explore/mlx-swift) plus [mlx-audio-swift](https://github.com/Blaizzy/mlx-audio-swift) for on-device MLX TTS/STT/STS, and mlx-swift-lm or llama.cpp bindings for the tutor LLM. The audio Swift SDK documents macOS 14+, Apple Silicon, async APIs, streaming audio, and model downloads. Pin versions and confirm each model’s license separately.
- **Core ML:** best path for compiled fixed models and ANE execution, especially a stable Kokoro/Whisper/Phi-sized model, with native Swift APIs. Conversion coverage lags the fast-moving research models; conversion may alter quality and memory.
- **llama.cpp:** GGUF quantized text models, Metal acceleration, mature Swift/C interface; strong fallback when a model is not in MLX.
- **ONNX Runtime:** Piper and some Kitten/Kokoro exports; cross-runtime portability, but check whether macOS execution provider actually uses ANE/GPU rather than CPU.
- **Python sidecar:** fastest route to prototype MLX-Audio, but adds packaging, startup, IPC, sandboxing and accessibility integration work. Keep audio streaming over local IPC and stream chunks rather than writing temp files.

## Full-stack RAM budget (planning estimates, not measured resident sets)

| Component | Suggested artifact | Approximate active RAM planning range |
|---|---|---:|
| OS + Swift app, audio buffers, UI | macOS, browser/apps closed for benchmark | 3.5–5 GB |
| ASR + VAD | Whisper small/base or Parakeet 0.6B quantized; stream/unload after final | 0.8–2.0 GB |
| Tutor LLM | Qwen3 4B Q4, context 4–8k | 3.0–4.5 GB (weights + KV/runtime) |
| Kokoro TTS | 82M MLX/Core ML | 0.8–1.4 GB |
| **Steady total** | **Components resident for overlap/cancellation** | **8.1–12.9 GB** |
| **16GB practical headroom** | **Prefer Qwen3 1.7B–4B, low context, release ASR buffers before TTS; avoid multiple models loaded** | **target <13 GB app+model footprint** |
| **32GB comfortable** | **Qwen3 4B–8B or Gemma 3n/4B, streaming ASR, Kokoro or Qwen3-TTS** | **10–18 GB; larger expressive TTS can fit if scheduled** |

Unified memory is shared with GPU and OS; model file size is not peak memory. Do not load a 4B LLM, Whisper large-v3, and 1.7B TTS concurrently on the 16GB floor. Use small streaming ASR (or unload it after transcription), cap LLM context, quantize, and synthesize short chunks. On 32GB, an expressive 0.6B–1.7B TTS can coexist if tested; reserve >8 GB for OS/app/working buffers.

## Recommendation for MVP

- **Primary TTS:** Kokoro-82M MLX (or Core ML if quality and timing match), English plus Spanish voice evaluation. Fast start, small memory, permissive license, ample voices. **Fallback:** AVSpeechSynthesizer, which is built-in, native, and stoppable; it keeps first launch and recovery graceful. Offer Pocket TTS or Qwen3-TTS later for cloning/expressive voice only after weight and voice-data terms are cleared.
- **Primary tutor LLM:** Qwen3 4B instruct Q4 on 32GB; on 16GB start with Qwen3 1.7B or 4B Q4 under 4k context after measuring; focus response style on short Socratic turns. **Fallback:** Gemma 3n E2B/3B-class artifact if its custom terms and tutoring evaluations pass; Phi-4-mini 3.8B is an English-first alternative. Qwen3 license and multilingual ability make it the safest first prototype, not a guaranteed winner in pedagogy.
- **RAM:** 16GB: budget 3.5–5 GB system/app, 1–2 GB ASR/VAD, ~2 GB LLM weights plus 1–2 GB cache/runtime for a 1.7B model (or ~4 GB total for 4B), and ~1 GB Kokoro; target 9–12 GB model/app working set and keep 3+ GB headroom. Serialize ASR teardown/loading and audio generation if needed. 32GB: use 4B–8B LLM (~4–8 GB active), 1–3 GB ASR and 1–4 GB TTS/runtime; target 12–20 GB app stack with ample system headroom.
- **Duplex verdict:** Cascaded STT → text LLM → chunked TTS is MVP. Implement semantic turn-end detection, partial captions, stream the answer, speak sentence/phrase chunks as soon as safe, and cancel playback/generation on barge-in. Test Moshi and LFM2.5-Audio as later opt-in experiments; neither currently has enough verified M1 Pro latency, memory, and tutor-quality evidence to be the primary stack.
- **Before release:** blind listening on English and Mexican Spanish; rubric score tutoring (asks before explaining, adapts level, correctness); measure cold/warm TTFT, time-to-first-audio, interruption latency, peak memory, battery/thermal behavior, and license provenance per exact model/voice artifact.
